# CAT WARS — build specification (EVM)

1v1 cat fights. Players bet native ETH on the RED cat (side 0) or the BLUE cat (side 1). The fight is simulated **on-chain**
from a Chainlink VRF random word. Winning bettors split the whole pot pro-rata to their stake, minus a small rake.
Anyone can replay any fight from its published seed and get the identical result.

Words MUST / MUST NOT are hard requirements. Anything not specified: choose the simplest safe option and document it.

## 2. Contracts

Solidity ^0.8.24, Foundry, OpenZeppelin (`Ownable2Step`, `ReentrancyGuard`, `Pausable`),
Chainlink `VRFV2PlusWrapperConsumerBase` + `VRFV2PlusClient` (VRF v2.5 **direct funding, paid in native ETH**), from
`@chainlink/contracts`: `src/v0.8/vrf/dev/VRFV2PlusWrapperConsumerBase.sol` and `src/v0.8/vrf/dev/libraries/VRFV2PlusClient.sol`.
Note: the consumer base constructor calls `wrapper.link()`, so test mocks must implement `link()`.

Two contracts only: `CatWarsEngine` (library, verbatim) and `CatWars` (game). The launch token is separate and is NOT used by the game.

### 2.1 Constructor (deployment receives no ETH and no post-deploy calls)

```solidity
constructor(address vrfWrapper, address owner_)
```
- `vrfWrapper` — Chainlink VRFV2PlusWrapper of the target chain:
  - Ethereum Sepolia (11155111): `0x195f15F2d49d693cE265b4fB0fdDbE15b1850Cc1`
  - Ethereum mainnet (1): `0x02aae1A04f9828517b3007f83f6181900CaD910c`
- `owner_` — the launch `$owner`. Initial `treasury = owner_`, `keeper = owner_`.
- Everything else starts at the defaults in 2.3. The contract MUST be fully usable with zero setup calls.

### 2.2 Round lifecycle

```
Open ──(now ≥ lockAt, requestResult)──▶ Requested ──(VRF callback)──▶ Fulfilled ──(settle)──▶ Settled
  │                                         │
  └─ one side empty at requestResult ──▶ Cancelled ◀── timeouts (anyone) ──┘
```

| Function | Who | Rules |
|---|---|---|
| `openRound(uint8 catA, uint8 catB)` | owner or keeper | `whenNotPaused`; `catA != catB`, both `< 8`; the previous round (if any) must not be `Open`. `lockAt = block.timestamp + bettingDuration`. Snapshots `rakeBps` into the round. Rounds are numbered 0,1,2,… |
| `placeBet(uint256 roundId, uint8 side)` payable | anyone | Round `Open`, `block.timestamp < lockAt`, `side < 2`, `msg.value ≥ minBet`. One side per address per round; extra bets on the same side add to the stake; the other side reverts. |
| `requestResult(uint256 roundId)` payable | **anyone** | Round `Open` and `block.timestamp ≥ lockAt`. If either side total is 0 → `Cancelled`, refund `msg.value`, no VRF. Otherwise `price = vrfPrice()`; require `msg.value ≥ price`; call `requestRandomnessPayInNative(CALLBACK_GAS_LIMIT, 3, 1, extraArgs(nativePayment=true))`; refund `msg.value − price` to the caller; store `requestId → roundId`, `requestedAt`; status `Requested`. **Player stakes MUST NEVER pay for VRF.** |
| `fulfillRandomWords(requestId, words)` | VRF wrapper only | MUST NOT revert and MUST stay cheap: if the mapped round is `Requested`, store `words[0]` and set `Fulfilled`; otherwise do nothing. No fight simulation here. |
| `settle(uint256 roundId)` | **anyone** | Round `Fulfilled`. `seed = bytes32(randomWord)`. `(winner, turns,,) = CatWarsEngine.simulate(catA, catB, seed)`. `pool = total0 + total1`; `rake = pool * round.rakeBps / 10_000`; credit `rake` to `owed[treasury]`; status `Settled`; emit seed, winner, turns. |
| `cancelRound(uint256 roundId)` | owner/keeper while `Open`; **anyone** if `Open` and `now > lockAt + 1 hours`; **anyone** if `Requested` and `now > requestedAt + 24 hours` | Status `Cancelled` (everyone refunded). Owner/keeper MUST NOT be able to cancel `Requested` or `Fulfilled` rounds. |
| `claim(uint256 roundId)` / `claimFor(uint256 roundId, address player)` / `claimMany(uint256 roundId, address[] players)` | **anyone** | Pays the player (never the caller): `Cancelled` → stake back; `Settled` and on the winning side → `stake * (pool − rake) / winningSideTotal`. Mark claimed **before** sending. Send with `call`; if the send fails, add the amount to `owed[player]` instead of reverting (`claimMany` must not be blocked by one bad receiver). Losing bets: `claim` reverts, `claimMany` skips them. |
| `withdraw()` | anyone with `owed[msg.sender] > 0` | Pays and zeroes `owed[msg.sender]` (treasury rake and failed sends). |

All money-moving functions are `nonReentrant` and follow checks-effects-interactions. All divisions round down; leftover dust stays in the contract.

### 2.3 Admin (owner only, bounded, never touches player funds)

| Setting | Default | Bounds |
|---|---|---|
| `rakeBps` | 500 (5%) | ≤ 1000 (10%). Affects only rounds opened afterwards (snapshot). |
| `bettingDuration` | 300 s | 60 s … 1 day |
| `minBet` | 0.001 ether | > 0 |
| `treasury` | owner | ≠ 0 |
| `keeper` | owner | any |
| `pause()` / `unpause()` | — | Pause blocks **only** `openRound`. Bets in open rounds, `requestResult`, `settle`, `cancelRound`, `claim*`, `withdraw` MUST keep working. |

`CALLBACK_GAS_LIMIT = 150_000` (constant). The owner MUST NOT have any way to move ETH except receiving `owed[treasury]`.
No upgradeability, no `selfdestruct`, no arbitrary external calls, no `receive()` other than what the VRF base needs.

### 2.4 Views for the frontend and keeper

`currentRoundId()`, `roundCount()`, `getRound(id)` (all fields incl. totals, bettor counts, status, lockAt, rakeBps, randomWord, winner, turns),
`getBet(id, player)` (side, amount, claimed), `pendingPayout(id, player)`, `vrfPrice()` (= wrapper `calculateRequestPriceNative(CALLBACK_GAS_LIMIT, 1)` at the current gas price),
`owed(addr)`, the admin settings, `CATS_COUNT = 8`.

### 2.5 Events (indexed `roundId`, `player` where present)

`RoundOpened(roundId, catA, catB, lockAt, rakeBps)`, `BetPlaced(roundId, player, side, amount, total0, total1)`,
`ResultRequested(roundId, requestId, price)`, `RandomnessFulfilled(roundId, randomWord)`,
`RoundSettled(roundId, seed, winner, turns, pool, rake)`, `RoundCancelled(roundId)`,
`Claimed(roundId, player, amount, sent)`, `Withdrawn(account, amount)`, plus one event per admin change.

### 2.6 Solvency invariant

At every point: `address(this).balance ≥ Σ stakes of Open/Requested/Fulfilled rounds + Σ unpaid winnings/refunds of Settled/Cancelled rounds + Σ owed`.

## 3. Tests (Foundry, all MUST pass)

1. `reference/test/CatWarsEngine.t.sol` verbatim — 500/500 vectors.
2. Full lifecycle with a mock `VRFV2PlusWrapper` (implements `link()`, `calculateRequestPriceNative`, `requestRandomWordsInNative`; records the request and exposes `fulfill(requestId, word)` that calls the consumer's `rawFulfillRandomWords`):
   - several bettors on both sides, top-ups, side switch reverts, bet after lock reverts, below `minBet` reverts;
   - `requestResult` before lock reverts, underpayment reverts, excess is refunded, VRF never paid from stakes;
   - after `settle`: the winner equals `CatWarsEngine.simulate(catA, catB, bytes32(word))`; every winner receives exactly `stake * (pool − rake) / winningTotal`; treasury `owed` equals the rake; losers get nothing.
3. One-sided round → cancelled at `requestResult`, full refunds, no rake, no VRF.
4. Timeouts: anyone cancels `Open` after `lockAt + 1h`, `Requested` after 24h; not earlier; owner cannot cancel `Requested`/`Fulfilled`.
5. Fulfill for an unknown/stale request does not revert and changes nothing. Double fulfill ignored. Double settle reverts.
6. Claims: double-claim reverts; `claimFor` by a third party pays the player; a reverting receiver contract gets credited to `owed` and can `withdraw`; a reentrancy attacker cannot drain.
7. Rake snapshot: changing `rakeBps` mid-round does not affect that round; `rakeBps > 1000` reverts.
8. Pause blocks only `openRound`.
9. Stateful fuzz / invariant test of the solvency invariant (2.6) across random bets, rounds, fulfils, settles, cancels, claims.
10. Gas report for `settle` (expected ≲ 600k worst case).

## 4. Website

Single-page app, mobile-first, dark theme matching `ui-reference/index.html` (two cat cards RED vs BLUE, center timer ring, pot, tug bar, backers list, fight replay overlay, result overlay with payouts).

- Wallet connect (injected wallets such as MetaMask/Rabby, plus WalletConnect). Read-only mode without a wallet. Switch-network prompt if on the wrong chain. Show a **TESTNET** badge on Sepolia.
- Live data from the contract (deployment addresses/ABIs from the launch deployment): current round, cats, stats/skills (from `engine/engine.js` `CATS`), countdown to `lockAt`, totals, pool %, payout multiplier `(pool − rake)/sideTotal`, backers list from `BetPlaced` events, the connected wallet's bet.
- Bet: amount input with chips, side buttons, `placeBet` with clear pending/confirmed/error states.
- When a round settles: replay the fight in the overlay with `engine.simulate(catA, catB, engine.hexToSeed(seedHex))` where
  `seedHex` is `randomWord` as **32-byte big-endian hex** (exactly `bytes32(randomWord)`, e.g. viem `toHex(randomWord, { size: 32 })`, or the `seed` field of `RoundSettled`); the replay winner MUST equal the on-chain winner (show a "verified ✓" note and the seed). Then the result overlay with the user's outcome.
- "Claim" for the user's unclaimed winnings/refunds across past rounds, and `withdraw` for `owed`.
- History of recent rounds (matchup, winner, pool, seed, link to the block explorer).
- Portraits from `art/catart.js` (also used in the fight overlay and result screen).
- Footer disclaimer: "Experimental game. Only play where online wagering is legal for you. 18+."
- No fake bots, no fake balances, no simulated bets anywhere.

## 5. Keeper script (in the contracts repo, `keeper/`)

Node 22 + viem. Env: `RPC_URL`, `PRIVATE_KEY` (keeper), `GAME_ADDRESS`. Loop:
open a round with a random matchup (never the same pair twice in a row) when none is `Open` →
wait for `lockAt` → `requestResult` with `value = vrfPrice() * 1.2` → wait for `Fulfilled` → `settle` →
`claimMany` for all winners (or all bettors if cancelled) in batches → repeat. Idempotent and restart-safe
(on start, resume whatever state the latest rounds are in). Log one line per step.
